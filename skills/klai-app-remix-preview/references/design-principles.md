# Design principles (anti-slop)
Judgment checks, not a template. Break one when the user profile or content calls for it, and note why in the record.

- Content first. Real content from the source or realistic mock data in the client's domain; no lorem or generic hero copy. Buttons use the app's own action words. No stock-photo heroes, no sparkle, rocket or brain icons, no emoji bullets.
- Cards earn their place. Use a list rather than a card grid when users scan for one item. Use left thumbnails only when each item has its own real image (avatar, product photo, logo), never a repeated generic icon. At most one thumbnail collection per page (unsourced judgment call). Vary density rather than uniform grids.
- Restrained labels. At most one eyebrow per page, and only when it adds a status, date or step the heading lacks.
- Restrained colour. One accent colour per theme for primary actions, focus and selection; everything else neutral. No default indigo/violet gradients or gradient text. Text 4.5:1, large text and icons 3:1.
- Shape and rhythm. A radius scale (small on inputs, a little more on cards, modest on modals) rather than one value everywhere. No pill-shaped containers; pills only for tags or chips. Spacing in 4px multiples.
- Type hierarchy. A 4–6 step type scale; hierarchy from size, weight and colour together. Tabular numbers for times, money and counts.
- Layout follows the job. Working pages are left-aligned; only the cover may centre. Don't repeat one section pattern down or across pages. Header and navigation stay consistent.
- Purposeful motion. Motion only for feedback (hover, press, open/close, saved), around 150–250ms (timing is an unsourced judgment call). Celebration effects only on a real completion.
