# Direction inside a makeover

Write `DIRECTION.md` before replacing tokens if none was supplied. Same required lines as the direction skill: audience and jobs, character (no clean/modern/sleek/minimal/premium), material world, one or two moments, what stays quiet, mode map, copy before layout, tokens with provenance, name-swap.

Full template: [assets/direction-template.md](../assets/direction-template.md).

## Refinement vs replacement
This run **replaces**. The old look is evidence (what jobs exist, what is clutter) and anti-reference (do not keep its signature chrome). Do not "meet in the middle" by polishing discarded indigo.

If the user actually wanted to keep the identity, stop and use polish.

## Modes
Operate pages: precision, familiar controls, quiet chrome, richness in the named moments.
Cover/marketing pages: more expression, still product-specific nouns.
Do not apply cover energy to a dispatcher table.

This does not rewrite `klai-app-remix-preview`.

## Brand
Authorized public reference only. Manual extract, no installer. Provenance lines on tokens. No layout plagiarism.

## Approval
Dev makeover is reversible (CSS, slots, components). Do not add a wait after writing direction unless the user asked to review first. Production publish is not this skill.

## Copy before layout
Voice, verbs, empty/error strings first. Then structure. Then tokens.
